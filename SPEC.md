# Платформа промо-презентаций

Модель: **проект → категории (шаблоны) → API → персональная ссылка**.

Кабинет и конструктор пишут в Postgres. Плеер открывается только по короткой ссылке.

## Роли URL

| URL | Что это |
|-----|---------|
| `/app` | Кабинет: объекты, шаблоны, ссылки, ключ API, аналитика |
| `/app/projects/:code/templates/:template/edit` | Конструктор таймлайна |
| `/{publicId}` | Публичный плеер (9:16), без кнопок управления видео |
| `/{publicId}/preview.jpg` | JPEG для письма, если в конструкторе включено «Формировать картинку» |
| `/login` `/register` `/forgot` | Вход. Регистрация: `AUTH_REGISTRATION=open\|invite\|closed` |

Старые `#/editor` и `localStorage` как источник правды больше не используются. Черновик шаблона лежит в `templates.draft_config`. Гостевые ссылки читают только опубликованный `templates.config`; выдача ссылки черновик в эфир сама не поднимает (иначе гонка с автосохранением затирает публикацию).

После автопоказа плеер открывает меню (не оверлей кнопок на последнем кадре). У раздела в конструкторе можно выбрать, какое меню открыть после ролика — основное или любое добавленное через «+».

## Данные

- **Проект** — объект клиента (`code` в URL и в API). Медиа изолированы: `/media/projects/{code}/library|tts|music/`.
- **Шаблон** — категория для CRM. Код (`single`, `double`, `default`) передаётся как `category`.
- **Ссылка** — `publicId` + имя гостя. `externalId` уникален в проекте: повторный `POST` возвращает ту же ссылку (`reused: true`).
- **Ключ API** — `Authorization: Bearer pk_…` для CRM, без логина в кабинет.
- **amoCRM** — OAuth на объект (кабинет → Интеграции). Webhook `POST /api/v1/amocrm/webhook/{pk_live_…}`: id сделки → API amo → имя гостя → ссылка. При выдаче и смене этапа пишется снимок `crm_status_id` / `crm_pipeline_id` и история в `link_crm_events`. Карта статусов → шаблонов (`amo_status_maps`): тот же `publicId`, другой ролик. Приоритет: явный `category` → карта → default. Callback: `GET /api/v1/amocrm/oauth/callback`.

Выдача:

```
POST /api/v1/projects/{code}/links
{ "name": "Иван", "category": "default", "externalId": "crm-123" }
→ { "ok": true, "reused": false, "url": "https://…/x7k2m9q", "publicId": "x7k2m9q" }

POST /api/v1/amocrm/webhook/{pk_live_…}
→ id сделки → OAuth → имя + status_id → ссылка (+ снимок/история CRM) → { "ok": true, "url": "https://djinal.2wel.ru/…" }
```

Документация с curl, amo-URL и полями — в кабинете, страница API.

## Аналитика

События по ссылке (время — Москва, период выбирается в кабинете):

- `open` — открыл презентацию
- `autoplay` — досмотрел автопоказ
- `menu` — зашёл в меню
- `whatsapp` — нажал WhatsApp (воронка)
- `topic` — открыл тему из меню
- `contact` — клик по кнопке связи (`channel`: whatsapp / telegram / max / tel / sms / site / other)

Смена статуса amo (`link_crm_events`): при webhook пишется `last_event_type` / `prior_types` — какое действие гостя уже было к моменту смены этапа. В обзоре — блок «Статус CRM после действий».

Обзор: 4 KPI воронки, Radial «% открытий ссылок» (выданные за период), Area по дням, Line (% досмотра и кликов связи от открывших), Bar (темы и часы), Pie (устройства и каналы). Четвёртый KPI и линия «Связь» — все каналы (`contact`: WhatsApp / Telegram / MAX / звонок / SMS / …), не только WhatsApp.

Плюс устройство (телефон / планшет / компьютер) и час суток.

## Тариф

Тариф у проекта, не у пользователя. Уровни различаются **только объёмом** — возможности одинаковые везде. Свой домен, дополнительные шаблоны и аватар — отдельные услуги, вне уровней.

| Уровень | Ссылок в месяц | Цена |
|---------|----------------|------|
| `start` | 500 | 9 900 ₽ |
| `flow` | 1 000 | 16 900 ₽ |
| `max` | 1 500 | 24 900 ₽ |

Сверх пакета — 29 ₽ за ссылку. Ставка выше маржинальной цены шага между уровнями (14–16 ₽), иначе переход на следующий уровень клиенту никогда не выгоден и кнопка в кабинете бессмысленна.

Расчётный период привязан ко дню подключения (`projects.plan_period_start`), а не к первому числу. Расход — число ссылок, созданных внутри периода.

Переход инициирует клиент кнопкой в кабинете (`/app/projects/{code}/plan`):

- **повышение** — сразу, якорь периода не двигается, поэтому новый объём накрывает уже потраченное сверх пакета;
- **понижение** — с конца оплаченного периода, до этого висит в `pending_plan`;
- наступившие понижения применяются лениво, при любом чтении списка проектов.

Превышение пакета **не блокирует выдачу ссылок**: гость получает страницу в любом случае, разница уходит в счёт.

```
GET  /api/projects/{code}/plan   → уровень, период, расход, история
POST /api/projects/{code}/plan   { "plan": "flow" }
```

Повтор текущего уровня отменяет запланированное понижение. Все смены пишутся в `plan_changes` — по ней выставляется счёт.

## Медиа

| Что | Путь |
|-----|------|
| Фото | `/media/projects/{code}/library/…` |
| TTS | `/media/projects/{code}/tts/…` |
| Музыка | `/media/projects/{code}/music/ambient.mp3` |

Общие `/media/tts/` и `/media/music/` — наследие Джинала; новые файлы туда не пишутся. Для проекта `djinal` seed копирует старые TTS и музыку в папку проекта.

## Озвучка

Сервис и голос выбираются по объекту в кабинете (`/app/projects/{code}/voice`) и хранятся в `projects.tts_provider` / `projects.tts_voice`.

| Сервис | Голоса | Роль |
|--------|--------|------|
| `sber` | каталог SaluteSpeech (`Nec_24000`, `Bys_24000`, `May_24000`, `Tur_24000`, `Ost_24000`, `Pon_24000`, `Kin_24000`) | по умолчанию, виден всем |
| `elevenlabs` | из `ELEVENLABS_VOICES` / `ELEVENLABS_VOICE_ID` | только при `projects.tts_elevenlabs_enabled = true` |

```
GET  /api/projects/{code}/tts/voices        → выбранный голос и каталог
POST /api/projects/{code}/tts/voice         { "provider": "sber", "voice": "Bys_24000" }
POST /api/projects/{code}/tts/generate      { "text": "…" }
GET  /api/projects/{code}/tts/file/{name}   поток для кабинета (по сессии)
GET  /api/public/tts/{token}                поток для гостя (подписанная ссылка)
```

Файлы озвучки не отдаются напрямую: `/media/**/tts/**` закрыт в nginx, а в конфиг гостя вместо пути подставляется подписанный токен со сроком `TTS_LINK_TTL_HOURS`. Смена голоса не переписывает уже сгенерированные файлы — кэш считается по **тексту + id голоса** (и настройкам ElevenLabs).

Если в `ttsText` есть `{name}`, файл не запекается в шаблоне: при `POST …/links` и при открытии ссылки озвучка собирается (или берётся из кэша) уже с именем гостя.

## Ограничения

- Логин: 10 попыток / 15 мин с IP
- Регистрация: 5 / час с IP
- `POST /api/v1/…/links`: 120 / мин на ключ (20 / мин с IP без ключа)
- Генерация озвучки: 200 / час на объект, текст до 1200 символов

## Запуск

```bash
cd web && npm run dev          # http://localhost:5173
docker compose up db -d && cd api && npm start
```

Плеер: `http://localhost:5173/{publicId}`  
Кабинет: `http://localhost:5173/app`
